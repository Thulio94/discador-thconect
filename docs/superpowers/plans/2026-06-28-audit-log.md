# Central Multi-Tenant Audit Log Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add an immutable, sanitized audit log for authentication and administrative changes, with tenant-isolated consultation and controlled Super Admin purging.

**Architecture:** A dedicated `AuditLogService` is the only write entry point, Eloquent observers capture company/license/user changes, and Laravel authentication listeners capture login/logout/failure. A shared query service powers separate Super Admin and tenant controllers, while purge remains isolated behind a Super Admin-only service and route.

**Tech Stack:** PHP 8.3, Laravel 12, Blade, Alpine.js, MariaDB 11.4, PHPUnit, Docker Compose, Vite.

- [ ] **Step 4: Implement transactional purge**

`AuditPurgeService` must expose `estimate(array $data): int` and `purge(array $data, User $actor): int`. Both methods reuse one private scoped query so the displayed estimate and deletion target cannot diverge. The purge method must:

1. Build a query scoped to one company or `whereNull('company_id')` for global events.
2. Apply `created_at` from start-of-day through end-of-day.
3. In a transaction, count and delete matching rows.
4. If count is zero, return 0 without creating an event.
5. Record `audit.purged` after deletion with company ID when applicable and metadata containing `deleted_count`, `date_from`, `date_to`, `scope`, and `reason`.
6. Return the deleted count.

Because the new event uses the current timestamp after the delete, it cannot be part of the deleted selection.
